# 問題の解決の助言を書く

速い層が先に進めなくなっている問題について、解決のための助言を `game_notes/<ゲーム>/advice.md` に書き直す。`<ゲーム>` は advisor への指示で渡されたゲーム名にする。
速い層 (画面を見て、問いごとに型付きの判断を返すモデル) は、助言に書かれている場面に今の画面が当てはまるときだけ、このファイルを参考にする。

## 書くこと

advice.md は、次の節で書く。

### 対象の場面

- 助言が当てはまる画面の様子を、速い層が今の画面と照らし合わせられる言葉で書く (例: 画面の中央に青い扉があり、左下に鍵のアイコンが出ている)

### 起きている問題

- 何が起きているか (例: 扉の前で A を押しても開かず、同じ場所に戻される)
- 何回繰り返したか (操作の記録から数える)

### 原因の見立て

- 問題が起きている原因の見立て。確かめていないことは (推測) と書く

### 試す手順

- 番号付きで、押すボタンとスティックの向きを具体的に書く (例: 1. 左スティックを上に倒して扉に近づく 2. 扉の前で止まったら A を 1 回短く押す)

### 試して効果が無かったこと

- 試しても効果が無かった操作を書く (同じ手順を繰り返させないため)

## 書き方

1. `game_notes/<ゲーム>/advice.md` と、ほかの 3 ファイル (controls.md・tips.md・strategy.md) を読む
2. context.md と画像、操作の記録から、速い層が先に進めなくなっている原因を考える
3. 前の助言で問題が解決していれば、その記述は消す。解決していなければ、効果が無かった手順を「試して効果が無かったこと」に書き、新しい手順を書く
4. 確かめた事実と推測を分けて書く。事実の行には観察の回数と、根拠にした画像のラベルを添える
   - 事実: `- 扉の前で A を押しても開かない (観察 4 回、根拠: 直近 5/5 (0.00 秒前))`
   - 推測: `- (推測) 鍵を持っていないと開かない (観察 1 回)`
5. ファイルは速い層の要求に毎回そのまま入るため、短く保つ。1500 字以内を目安にする
6. 書き換えてよいのは advice.md だけ。ほかの 3 ファイルは読むだけにする
